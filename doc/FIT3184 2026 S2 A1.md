## 1. Synopsis and Background

Parking in the Central Business District (CBD) is often challenging, leading to traffic congestion and driver frustration, as drivers may need to circle to find parking. To address this, a new startup has been formed to develop a smart parking platform that helps users find available car parks and parking lots. The platform will be powered by the You Only Look Once (YOLO) machine-learning vision model. This platform analyses real-time video feeds from car park operators to identify and communicate the most likely available parking spaces to users. As a startup, they don’t have much funding, so they decided to hire a full-cycle/full-stack Cloud software engineer (you) to do everything.

This project requires developing a highly scalable, web-based system hosted in a public cloud (GCP, Oracle, Azure) to serve as the backbone of this startup. End users (simulated by automated test scripts) will send HTTP requests to your RESTful web service. The system will process car park images using pre-trained machine learning models and return a structured payload detailing the detected available parking spots, alongside an annotated image if requested. It also provides a simple dashboard that gives the platform operator a high-level overview of the operation.

The web service **must** be developed using **Python's FastAPI** framework. The application will be containerised using Docker and orchestrated using a managed Kubernetes cluster.

## 2. Project Objectives

This project assignment evaluates competency in cloud-native development, distributed systems, and performance engineering through the following core objectives:

- **API Development:** Constructing a Python-based RESTful API using FastAPI to handle image payloads, perform blocking or asynchronous ML inference safely, and return structured JSON and base64-encoded annotated images. As this is a cloud computing unit, you only need to use the pretrained model; model training or tuning is not required.

- **Containerisation:** Packaging the Python application and system dependencies into an optimised, lightweight Docker image. Making the model loadable and updatable without rebuilding the image.

- **Container Orchestration:** Deploying the containerised application, configuring Kubernetes Deployments and Services (LoadBalancer), and managing strict pod resource requests and limits.

- **Performance Benchmarking:** Using Locust to simulate high-concurrency traffic and measure system latency, throughput (queries per second), and failure rates while keeping resource limitations in mind.

- **Empirical Reporting (500 words):** Analysing system bottlenecks, cost, processing efficiency, and horizontal scaling characteristics in a concise, data-driven benchmark report.

## 3. The Web Service Architecture

You must develop a RESTful API using the FastAPI framework. The service should be capable of efficiently handling multiple concurrent clients. The web service creates asynchronous task handling for each incoming request, utilising the YOLO engine to detect objects in the image. After your initial discussion with the startup founder, you drew up and agreed on the following architecture for your first iteration:

![Architecture diagram](images/architecture.png)

#### **Components**

- **Users & Clients / End Users:** Simulated by automated scripts, these act as the primary API consumers, submitting car park search requests via **HTTP** **Requests** and receiving parking availability data (JSON payload) and, if requested, an **Annotated** **Image** (with bounding boxes) in the **REST API** **Response**.

- **Car Park Operator Camera:** The continuous source of video stream/images from security cameras installed at parking facilities. To conserve bandwidth, the cameras don’t continuously send data to our platform; instead, we send an HTTP GET request to the cameras to request an image of the car park.

- **Platform Operator:** The human administrator who manages the system and requires access to operational dashboards. The platform operator should be able to see car park status and the number of available parking spaces.

- **Google Kubernetes Engine (GKE) Cluster:** The managed Kubernetes environment for automating deployment, scaling, and operational management of application containers.

- **FastAPI Pods (Docker, Python):** The containerised Python web application, built with FastAPI and packaged using Docker, which processes user requests and requests camera images. The visual representation shows multiple replicated pods for handling high traffic.

- **Container Registry:** A private Docker image repository where finalised application images are securely stored and from which GKE pulls them to instantiate pods.

- **Pre-trained YOLO Models:** The real-time object detection logic running *within* the FastAPI application to analyse car park images and identify vehicles and empty spots.

- **Monitoring Dashboard:** Visualises system metrics and status, allowing platform operators to proactively detect and resolve issues.

### 4.3 Other Requirements

#### **Performance Optimisation**

Your application should be optimised to achieve higher concurrency/performance per node/container. For example, repeated requests from the same user can be cached. Also, as a cloud engineer, ask yourself lots of "what-if" questions, even for this simple application. For instance, what if the user sends a large n (n>100)?

#### **Stability and Scalability**

The platform must maintain service availability and performance under fluctuating traffic conditions. You must consider load balancing and scaling within the Kubernetes cluster to dynamically adjust replica counts based on CPU utilisation metrics. Furthermore, all pods must be configured with explicit resource requests and limits to ensure predictable resource allocation.

#### **Updateable Model**

Machine learning models evolve rapidly through continuous retraining and data updates. Baking large model weights directly into container images causes massive image bloat, sluggish scaling, and inefficient registry storage. This practice tightly couples the rapid data lifecycle of parameters with the slower release cycle of application code. Hence, the application shall keep container images lightweight and mount model weights dynamically at runtime. You shall design a mechanism to implement this feature.

#### **Project Cost Planning and Control**

You shall manage cloud costs carefully during the development, deployment, and demo periods. As a guideline, the whole project should cost less than $20.

#### **Application Logging**

The application must implement comprehensive logging and tracing to ensure system observability and facilitate debugging. All logs must capture essential request metadata, including timestamps, severity levels (e.g., DEBUG, INFO, ERROR), service name, and unique request/user UUIDs.

## 5. Load Generation and Performance Metrics

Using Locust, you will write a Python load-generation script to simulate concurrent user access to your API. The script must continuously send requests to your core API to simulate end-user traffic. **Hint:** Because machine learning inference is highly CPU-bound, achieving high concurrency in Python requires careful architectural management. If you simply execute the synchronous YOLO prediction inside a standard asynchronous FastAPI route, you will block the main event loop, causing catastrophic latency spikes for all concurrent requests.
